1 · Overview

This project is a single, coherent Foundry reference implementation that proves Foundry natively solves 50 recurring data-engineering problems, using the NHS RTT (Referral-To-Treatment) dataset. The primary user is Clare, an RTT operations manager; the IG owner is Nitin.

Domain facts (used verbatim)

RTT clock target = 18 weeks. 52 and 65-week waits are nationally reportable breaches. Constitutional standard = 92% within 18 weeks. PTL = Patient Tracking List.

Shape of the data

~1,200 pathways across 5 trusts and 10 specialties. nhs_number is PII. IG rules (SAE) drop sex, age_at_referral, source_load_ts before Silver leaves the layer.

Design rule

Every choice traces to a constraint: legal/PII, performance, cost, or Clare’s real need. Lightweight engines by default; Spark only where a shuffle is genuinely warranted.

Verified control totals from the actual build: typed 1,215 = clean 1,205 + quarantine 10 (reconciled), PK unique 1,205/1,205, SAE removed 3 columns, freshness monitor flags the data stale (541 days).

Bronze

raw_ingest.py types the all-string landing; unparseable values become null and are flagged (never dropped).

Silver

clean_silver.py canonicalises + validates and quarantines bad rows; sae_minimise.py removes IG columns; metrics.py adds clinical flags.

Gold

marts.py builds the trust×specialty performance mart and the PTL for Clare.

Ontology backing

security.py pseudonymises nhs_number and drops it, producing the PII-free dataset behind the Pathway object.

3 · Code flow, stage by stage

Each stage reuses a unit-tested function from lib/, so “the test that proves the function also proves the pipeline column”.

1

seed.py — reproducible sources Problem 19

Materialises the 4 source tables deterministically (25 verbatim rows + 1,175 seeded valid rows + 15 documented dirty rows). The raw pathway table is emitted as all strings (CSV-landing shape) so we can demonstrate real type validation downstream.

@transform.using(out=Output(paths.RTT_PATHWAYS_RAW))
def seed_rtt_pathways_raw(out):
    out.write_table(pl.DataFrame(_raw_pathway_rows(),
        schema={c: pl.Utf8 for c in _PATHWAY_COLS}, orient='row'))
2

raw_ingest.py — ingest-time typing P6 P10

Casts referral_date, weeks_waited, age_at_referral, source_load_ts using the tested parsers in lib/canonicalise.py. Bad casts become null and are flagged (weeks_parse_failed, date_parse_failed). WARN checks on raw; nothing is dropped here.

pl.col('weeks_waited').map_elements(C.to_int, return_dtype=pl.Int64)
pl.col('referral_date').map_elements(C.parse_date, return_dtype=pl.Date)
3

clean_silver.py + lib/dq_rules.py — canonicalise & quarantine P1 P8 P34 P35 P40 P41 P42

Canonicalises free-text specialty to the reference (T&O → Trauma and Orthopaedics), joins the dimensions, then applies the quarantine policy in one tested place. Rows that fail any rule are routed to /quarantine with a reject_reason; a recon dataset proves clean + rejects = input. FAIL Data Expectations on the clean output stay green because the policy works.

df = dq_rules.add_reject_reason(df, valid_trusts, SNAPSHOT, MAX_WEEKS)
clean   = df.filter(pl.col('reject_reason').is_null())
rejects = df.filter(pl.col('reject_reason').is_not_null())
4

sae_minimise.py — IG data minimisation P29 P31 P48

Reads sae_column_rules (metadata-driven, not hard-coded) and drops sex, age_at_referral, source_load_ts. A hard post-condition fails the build if any banned column survives, and an audit log records who/what/when.

if not S.assert_minimised(minimised.columns, _MUST_BE_ABSENT):
    raise ValueError('SAE minimisation failed: banned column present')
5

metrics.py + lib/rtt_metrics.py — clinical flags P35

Adds is_breach_18w, is_52w_breach, is_65w_breach, wait_band, rag_status via the tested metric functions (18-week target, 52/65-week reportable breaches).

6

marts.py — Gold outputs

rtt_trust_specialty_perf (% within 18 weeks + the 92% constitutional flag) and rtt_ptl (active pathways, longest-wait first, RAG + breach flags) — the screen Clare runs each week.

7

security.py + lib/pii.py — PII protection P29 P31

Pseudonymises nhs_number (SHA-256) and drops the raw value, producing the PII-free dataset that backs the Pathway object. A post-condition asserts nhs_number never leaves.

6 · Performance & cost — the right engine for the job

Lightweight by default

The whole medallion runs on Polars/DuckDB single-node (P28 P45 P46). cost.py pins @lightweight(1 core / 2 GB) (P26 P27).

Spark only when needed

perf.py demonstrates AQE, broadcast join, salting the hot TR005 key, caching, column pruning, partitioned + bucketed writes and compaction (P4 5 11 12 13 22 23 24 25).

10 · Test strategy & CI

Unit (pytest)

11 modules over lib/ with deterministic fixtures; every rule has a negative case.

Data Expectations

FAIL where a bad row corrupts keys/joins/metrics; WARN for signals. Bad rows are quarantined, so FAIL checks stay green because the policy works.

Integration

Reconciliation, PK uniqueness, quarantine breakdown, SAE removal, CDC/SCD2 counts, partition/bucket layout.

CI

Every commit runs pytest + ci/foundry-publish; merge to master only when green.
