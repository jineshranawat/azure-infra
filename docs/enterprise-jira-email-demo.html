From the repo root (e.g. D:\azure):

2.6 run_incident_flow.py — step detail

  1. Read JIRA_BASE_URL / NOTIFY_MAIL_URL / OWNER_EMAIL from env (defaults: localhost + training@example.com).
  2. wait_healthy until both services answer /health.
  3. Cmd always passes --force-fail true (happy path exists if you pass false).
  4. write_run_log → shared-adf-lab/enterprise-notify/out/adf-run-log-*.txt.
  5. Create issue summary like [ADF] pl_ntf_05_master_incident failed — run_id=….
  6. Attach that file; add comment that email is queued.
  7. POST mail with ticket key; write out/incident-result-*.json.

3. The enterprise story (WHAT / WHY / analogy)

Restaurant analogy:

Dinner service fails (burnt dish = ADF Fail activity).
Automatically open a maintenance ticket (Jira), staple the CCTV clip (run-log attachment), and text the manager (email).

What you build

On pipeline failure: create Jira issue → attach evidence → notify owner email.

Why it matters

2am failures need an audit trail + human wake-up — not Slack archaeology.

Critical constraint: Azure Data Factory and Databricks run in the cloud. They cannot call http://127.0.0.1 on your laptop.

That is why the lab has two layers with the same REST shape:

Local proofenterprise-notify.cmdJira UI + mail outbox
ADF activitiesFolder 15-enterprise-notifyFail / Web / Databricks in Studio
Real enterpriseJIRA_BASE_URL + Logic App URLAtlassian Jira + Outlook

3. Local demo — step by step detail

  1. Bootstrap
    enterprise-notify.cmd creates/uses .venv, pip-installs fastapi, uvicorn, httpx from requirements.txt.
  2. Start services (idempotent)
    start_services.py checks /health on ports 18080 and 18081. If already up → reuse. If down → start uvicorn in background.
  3. Incident flow
    client/run_incident_flow.py with --force-fail true:
    invents a failed ADF run → creates Jira → attaches log → posts mail JSON.
  4. Open browsers
    Board: http://127.0.0.1:18080/
    Inbox: http://127.0.0.1:18081/

6.1 Open ADF Studio

    Resource group should be rg-shared-class1.
  2. Click Launch Studio (blue button on Overview).

6.2 Find the enterprise notify folder

  3. Expand folder 15-enterprise-notify.

6.3 Inspect the master pipeline (before you run)

  1. Click pl_ntf_05_master_incident.
  2. On the canvas you should see three activity boxes:
    RunSimulateWork (Execute Pipeline → child 01)
    RaiseIncidentOnFailure (Execute Pipeline → child 04, depends on Failed)
    IfUseWebActivities (If Condition)
  3. Click blank canvas → right panel Parameters tab. Confirm defaults:
    force_fail = true
    use_web_activities = false ← keeps Azure from calling localhost
    jira_base_url = http://127.0.0.1:18080
    notify_mail_url = http://127.0.0.1:18081
    owner_email = training@example.com
  4. Click activity RaiseIncidentOnFailure → Settings → note dependency condition includes Failed on RunSimulateWork.
    Why: ticket/email only run when work fails — classic enterprise pattern.

6.4 Trigger the master from UI

  1. With pl_ntf_05_master_incident open → top toolbar Add trigger → Trigger now or use Debug (same parameters).
  2. Leave parameters as defaults for class → OK.
  3. Left rail → Monitor → Pipeline runs.
  4. Open the newest run of pl_ntf_05_master_incident.
Expected Monitor result:
• RunSimulateWork → Failed (intentional)
• RaiseIncidentOnFailure → runs (Succeeded or soft-fail inside notebook if localhost)
• Overall master often shows Failed because child 01 failed — OK for this demo

6.5 Drill into child runs

  1. In the master run details, click activity RunSimulateWork → open linked pipeline run.
  2. Inside pl_ntf_01: IfForceFail true branch → FailForcedIncident with error code PL_NTF-DEMO-FAIL.
  3. Back to master → open RaiseIncidentOnFailure → child pl_ntf_04 → activity RaiseJiraAndEmail.
  4. Open Databricks notebook output (Output tab) — JSON with jira_key or jira_error + hint to run local cmd.

7. Build this in your company — ADF Studio UI (from blank)

Recreate the pattern on a company factory (real Jira + Logic App). Same five pipelines; swap URLs/secrets for production.

7.0 Prerequisites (company)

ItemWhat you need
Data FactoryYour factory + Contributor access
JiraCloud URL, project key (e.g. OPS), API token, user email
EmailLogic App (HTTP trigger → Office 365 Send email) or approved webhook
OptionalDatabricks workspace + linked service (best for file attach)
Secret storeKey Vault for Jira token / Logic App URL (never hard-code in JSON)

7.1 Create folder

  1. ADF Studio → Author → Pipelines → ⋯ on Pipelines → New folder → name ops-incident-notify (or 15-enterprise-notify).
  2. Habit: add Parameters on each pipeline before activities so expressions resolve.

7.2 Pipeline A — simulate work or fail

  1. New pipeline → name pl_ntf_01_simulate_work_or_fail → move into folder.
  2. Parameters: force_fail (Bool, default true), run_id (String).
  3. Variables → New → work_status String.
  4. Drag If Condition → name IfForceFail.
  5. Expression:
    @equals(pipeline().parameters.force_fail, true)
  6. True → drag Fail → name FailForcedIncident
    Message: PL_NTF-DEMO-FAIL — raise Jira + email next
    Error code: PL_NTF-DEMO-FAIL
  7. False → Set variable MarkWorkOk → work_status = @string('ok').
  8. Publish / Save.
Test: Trigger with force_fail=true → Failed. With false → Succeeded.

7.3 Logic App for email (company portal)

  1. Portal → Create → Logic App (Consumption) → region per company policy.
  2. Designer → trigger When an HTTP request is received.
  3. Request Body JSON Schema:
    { "properties": { "to": { "type": "string" }, "subject": { "type": "string" }, "body": { "type": "string" }, "jira_key": { "type": "string" }, "run_id": { "type": "string" } }, "type": "object" }
  4. + New step → Office 365 Outlook → Send an email (V2)
    To → dynamic to · Subject → subject · Body → body
  5. Save → copy HTTP POST URL → store in Key Vault.

7.4 Pipeline B — Web create Jira

  1. New pipeline pl_ntf_02_web_create_jira.
  2. Parameters: jira_base_url, run_id, pipeline_name.
  3. Drag Web → name WebCreateJiraIssue.
  4. Settings:
    URL (Expression): @concat(pipeline().parameters.jira_base_url, '/rest/api/2/issue')
    Method: POST
    Header: Content-Type = application/json
    Auth: Basic (Jira email + API token) per company standard
    Body (Expression) — change OPS to your project key:
    @json(concat( '{"fields":{"project":{"key":"OPS"},"summary":"[ADF] ', pipeline().parameters.pipeline_name, ' failed — run_id=', pipeline().parameters.run_id, '","description":"Automated incident. Run ID: ', pipeline().parameters.run_id, '","issuetype":{"name":"Bug"}}}' ))
  5. Optional: Set variable jira_key = @activity('WebCreateJiraIssue').output.key for the email body.

Company tip: Multipart file attach is hard with Web alone. Use Databricks / Azure Function for attachments (Section 7.6), or attach via Logic App reading a blob.

7.5 Pipeline C — Web send email

  1. New pipeline pl_ntf_03_web_send_email.
  2. Parameters: notify_mail_url, owner_email, run_id, pipeline_name, jira_key.
  3. Web POST → URL = Logic App HTTP URL parameter.
  4. Body:
    @json(concat( '{"to":"', pipeline().parameters.owner_email, '","subject":"[Ops] ADF incident ', pipeline().parameters.run_id, '","body":"Pipeline ', pipeline().parameters.pipeline_name, ' failed. Run: ', pipeline().parameters.run_id, ' Jira: ', pipeline().parameters.jira_key, '","run_id":"', pipeline().parameters.run_id, '"}' ))

7.6 Pipeline D — Databricks notebook (create + attach + email)

  1. Databricks → Workspace → import / create notebook at /Shared/shared-adf/nb_incident_jira_email (source file in repo: shared-adf-lab/notebooks/nb_incident_jira_email.py).
  2. Widgets must match ADF base parameter names: run_id, jira_base_url, notify_mail_url, owner_email, …
  3. ADF → New pipeline pl_ntf_04_databricks_incident → drag Databricks Notebook.
  4. Linked service + notebook path → Base parameters map to @pipeline().parameters.….
  5. Notebook does: create issue → multipart attach run log → POST email.

7.7 Pipeline E — master

  1. New pipeline pl_ntf_05_master_incident with parameters (force_fail, URLs, owner_email, use_web_activities).
  2. Execute Pipeline RunSimulateWork → invoke pl_ntf_01 → Wait on completion = On.
  3. Second Execute Pipeline RaiseIncidentOnFailure → invoke pl_ntf_04 (or Web 02+03).
  4. On second activity → Settings → Activity dependency:
    Depends on: RunSimulateWork
    Condition: tick Failed only
  5. Optional If use_web_activities → true branch Execute 02 then 03.
  6. Publish all pipelines.

7.8 Wire to a real business pipeline

  1. Open your nightly load pipeline.
  2. After the risky Copy / Data Flow / ForEach, add Execute Pipeline with dependency Failed → invoke your incident pipeline.
  3. Pass @pipeline().RunId, @pipeline().Pipeline, owner from global parameter / Key Vault.
  4. DEV-only forced failure → confirm real Jira ticket + Outlook mail.
Company done when: DEV failure creates a real Jira issue + email; PROD uses Key Vault and real Failed dependencies (no force_fail flag).
