Kitchen fire (Fail) → maintenance ticket (Jira) → CCTV clip attached (run log) → text manager (email).

[1] Work fails (If + Fail) [2] POST /rest/api/2/issue → key FIN-n [3] POST .../issue/{key}/attachments → run log [4] POST mail webhook / Logic App → owner email

Notebook walkthrough (SOURCE file)

  1. Widgets — dbutils.widgets.text(...) then dbutils.widgets.get. Names must match ADF base parameters exactly.
  2. Helpers — _headers (optional Basic auth), http_json, http_multipart (boundary form-data + X-Atlassian-Token: no-check).
  3. Early exit — if not force_fail → dbutils.notebook.exit with skipped status.
  4. Build log text — in-memory run log string (same idea as local write_run_log).
  5. Create issue — POST {jira_base}/rest/api/2/issue → read key.
  6. Attach — multipart POST to .../issue/{key}/attachments.
  7. Comment — note that email is queued.
  8. Mail — POST to notify URL (append /notify for local sink).
  9. Soft-fail — catch exceptions into jira_error / mail_error (expected when URL is localhost from Azure cluster).
  10. Exit JSON — dbutils.notebook.exit(json.dumps(result)) for Monitor.
# Key notebook sequence (conceptual) created = http_json("POST", f"{jira_base}/rest/api/2/issue", {...}) jira_key = created["key"] http_multipart(f"{jira_base}/rest/api/2/issue/{jira_key}/attachments", f"adf-run-log-{run_id}.txt", log_text.encode()) http_json("POST", notify_url, {"to": owner_email, "subject": ..., "body": ..., "jira_key": jira_key}) dbutils.notebook.exit(json.dumps(result))

Why Databricks (not only Web) for attach

Jira attachment API needs multipart/form-data. ADF Web activity is awkward for binary uploads. Notebook / Azure Function is the enterprise pattern for attach.
