2. Workspace — folders & notebooks

~6 hours practice

When You need to find, open, rename, or organize notebooks and files in the workspace browser.

Workspace = the filing cabinets. /Shared = the shared staff room cabinet. /Users/you@… = your personal locker.

Nice step-by-step — open a class notebook

  1. Left nav → Workspace.
  2. Expand Shared (not Users, for shared-class labs).
  3. Open day7-day8 → click master_pyspark_complete.
  4. Or open day9 → pick a notebook from the class map (§13).
  5. Confirm the browser URL contains #workspace/Shared/… — that is the canonical path ADF and deploy scripts use.

Create a personal scratch notebook (optional)

  1. Workspace → Users → your email → right-click → Create → Notebook.
  2. Name it clearly (e.g. scratch_spark_notes). Language: Python.
  3. Do not put finished class solutions only under Users if the trainer expects Shared paths — deploys overwrite Shared.
Class rule: deploy-shared-lab.cmd / release.cmd databricks overwrite the same Shared paths. Re-running deploy refreshes content — it does not create notebook (1) copies. That is intentional CI behaviour.

3. Notebook editor — cells, run, attach

~12 hours (heart of every Spark day)

When Interactive coding, teaching, exploring data, debugging Spark — the default FinLedger learning surface.

UI anatomy (top → bottom)

ControlWhat it doesClass tip
Cluster selectorAttach / detach computeMust show a running cluster before Spark cells work
Run all / Run cellExecute codeRun cell-by-cell while learning; Run all for smoke tests
LanguagePython / SQL / Scala / R per cell via magic%sql, %md magics
Markdown cellsTeaching textMasters use lots of %md — read before run
Variables / widgetsParameters at topChange widget → re-run dependent cells
Spark UI / Driver logsDeep debug linksUse when a cell is slow or fails with executor errors

Nice step-by-step — first successful cell

  1. Open /Shared/day7-day8/master_pyspark_complete.
  2. Top bar → cluster dropdown → select finledger-lab (create it in §4 if missing).
  3. Wait until status is Running (green). Attaching can take 1–3 minutes on cold start.
  4. Find the first code cell after the intro markdown → click into it → Shift+Enter (run cell + move next).
  5. Read the output under the cell. If error mentions cluster / context — you are not attached; go back to step 2.
  6. Continue cell-by-cell. Do not skip setup cells that create SparkSession or read secrets.
# Typical first checks inside a notebook (after attach) spark dbutils.secrets.list("finledger")

4. Compute — clusters (all-purpose)

~8 hours including cost discipline

When You need Spark for notebooks. Jobs can use job clusters; interactive labs use an all-purpose cluster.

Compute = turning the ovens on. Auto-terminate = ovens switch off if nobody cooks — saves money.

Class cluster recipe

SettingValueWhy
Namefinledger-labEveryone recognises it
PolicyUnrestricted / default (as allowed)Training simplicity
Access modeSingle user (you)Storage key / secrets patterns work; Shared can block
RuntimeLatest LTS ML or standard (trainer choice)Stability
NodeSmallest viable (e.g. Standard_DS3_v2 class)Cost guardrail
Workers1 (or single-node if offered)Labs are small
Auto-terminate30 minutesMandatory habit

Nice step-by-step — create finledger-lab

  1. Left nav → Compute → Create compute (or Create cluster).
  2. Name: finledger-lab.
  3. Access mode: Single user → select your user.
  4. Pick a small node type; set workers to minimum; set auto-terminate to 30 minutes.
  5. Create → wait until state Running.
  6. Return to notebook → attach this cluster → run a cell.
  7. When you leave for lunch: Compute → cluster → Terminate (or trust auto-terminate).
Leaving a large cluster Running overnight burns budget. FinLedger cost notebooks and the laptop cost dashboard exist for a reason — treat Compute like a metered oven.

5. Workflows (Jobs) — scheduled & multi-task runs

~10 hours

When You need unattended runs, multi-notebook DAGs, or ADF to trigger a Job (not only an interactive notebook).

Notebook = cooking at the station interactively. Job = the printed ticket that runs even if the chef walked away.

Nice step-by-step — inspect a Job run

  1. Left nav → Workflows (sometimes labelled Jobs).
  2. Open Jobs list → pick a job (ADF lab may create/update jobs via scripts).
  3. Open Runs tab → click the latest run.
  4. See task graph, duration, Succeeded/Failed.
  5. Open failed task → view notebook output / error — same spirit as ADF Monitor activity Error.
  6. Correlate with ADF: if ADF Notebook/Job activity failed, ADF Error often links or names this run.

Use Jobs when…

  • ADF should start a versioned job id
  • Multiple tasks with dependencies
  • Schedules (cron) without ADF

Use notebook only when…

  • Learning / debugging cell by cell
  • One-shot ADF “Notebook” activity on a path
  • Class demos on Shared paths
flowchart LR
  ADF[ADF pipeline activity] -->|Notebook path| NB[Interactive notebook on cluster]
  ADF -->|Job id| JOB[Workflows Job run]
  JOB --> T1[Task: notebook A]
  JOB --> T2[Task: notebook B]
  NB --> OUT[Cell outputs]
  T1 --> LOG[Job run logs / UI]

6. SQL Editor & SQL warehouses

~8 hours

When You want warehouse-backed SQL (BI style), grants in SQL, or dashboards — not full PySpark notebooks.

Nice step-by-step — first SQL query

  1. Left nav → SQL → SQL Editor (wording varies).
  2. Select or create a SQL warehouse — start the smallest size; note it bills while Running.
  3. Write a simple query, e.g. SHOW CATALOGS; or SELECT 1;.
  4. Run → see results grid.
  5. For system tables (if granted): SELECT * FROM system.billing.usage LIMIT 10; — see /Shared/day9/system_tables_master and its doc.
  6. When done: SQL warehouses → Stop the warehouse.
SQL warehouses are a different meter from all-purpose clusters. Stopping the cluster does not stop the warehouse.

7. Catalog — Unity Catalog browser

~10 hours with medallion / governance labs

When Browse tables, schemas, volumes, lineage (if enabled), and permissions — the “data library” UI.

Catalog = the card catalog in a library. Schemas = shelves. Tables = books. Volumes = filing boxes for files.

Nice step-by-step — explore a table

  1. Left nav → Catalog.
  2. Expand a catalog → schema → table (or use search).
  3. Open Overview (columns, type), Sample data, Details.
  4. Use Permissions (if you are admin) to understand grants — do not revoke class grants casually.
  5. For FinLedger lakehouse labs, tables often appear after notebooks write Delta to UC or to the metastore paths taught in Day 9.
System catalog system needs Metastore Admin / grants — workspace admin alone is not enough. Trainers: see system tables master guide + account console steps.

8. Data explorer / Volumes / external locations (awareness)

~5 hours

When You need to see files (Volumes) or external locations governed by UC — complementary to ADLS in Azure Portal.

  1. In Catalog, look for Volumes under a schema.
  2. Browse files; compare with Portal ADLS containers bronze/silver/gold for the shared storage account.
  3. Remember: many FinLedger labs still use abfss:// + secrets for teaching storage keys — UC Volumes are the enterprise direction.

9. Secrets — scopes in the UI & in code

~4 hours

When Notebooks must read storage keys / tokens without hard-coding. Class scope: finledger.

Nice step-by-step — verify scope

  1. Prefer CLI/deploy for creation: deploy-shared-lab.cmd creates scope finledger with keys storage-account, storage-key.
  2. In a notebook on a running cluster:
    dbutils.secrets.listScopes()
    dbutils.secrets.list("finledger")
  3. Read a secret: dbutils.secrets.get("finledger", "storage-account") — value is redacted in UI output.
  4. If scope missing: re-run deploy or Session 3 secrets setup; do not paste keys into notebook cells.

10. Repos / Git folders

~6 hours (enterprise pattern; light in class)

When Enterprise CI clones git into the workspace. FinLedger class default is still Workspace import overwrite from laptop scripts.

  1. Left nav → Repos (if enabled) → Add repo → paste git URL (needs PAT / auth).
  2. Pull / branch as your org requires.
  3. For this course, prefer editing in git on the laptop → release.cmd databricks so everyone shares the same Shared paths.
Official direction: Databricks Asset Bundles + Repos for production. Class uses simpler overwrite to keep one Shared tree for 30 learners.

12. Settings & admin awareness (don’t break the class)

~4 hours awareness

  • User settings — theme, editor font — safe.
  • Workspace admin — users, cluster policies — trainer only.

Do not delete Shared folders, secret scopes, or other learners’ clusters.
