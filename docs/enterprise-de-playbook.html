1. Why these six (what & why)

Analogy: a restaurant kitchen. You don't only plate food — you check ingredients (DQ), cook only new tickets (watermark), send spoiled boxes to returns (quarantine), run the same recipe for many menu items from a clipboard (config ForEach), write the guest book (audit), and ring the manager when the oven fails (Jira+email).

Every production data engineer hits these patterns weekly. The local runners prove the logic end-to-end without waiting on cloud networking to your laptop. ADF folder 15-enterprise-notify and medallion / watermark pipelines are the Azure twins.

4. Each use case — flow + code

UC01 — Incident notify

Why: on-call must see failure with evidence, not dig Monitor alone.

scenarios/uc01_incident_notify.py → start_services.py (Jira :18080, mail :18081) → client/run_incident_flow.py --force-fail → out/uc01_incident_result.json
Board + outbox UIs · deep teach: enterprise-jira-email-demo.html

UC02 — Data quality gate

Why: never promote poison rows into silver/gold.

sample_data/good_transactions.csv → PASS sample_data/bad_transactions.csv → FAIL (bad channel / empty / non-numeric) → out/uc02_dq_gate_result.json

UC03 — Incremental watermark

Why: full reload every night wastes money and time; deltas are the default.

sample_data/watermark.json + good_transactions.csv → filter event_ts > last watermark → out/uc03_incremental_delta.csv → out/uc03_watermark_new.json

UC04 — Quarantine / dead-letter

Why: isolate bad files so one corrupt drop doesn't block the lake.

incoming/*.csv → DQ check PASS → out/uc04/loaded/ FAIL → out/uc04/reject/ → out/uc04_quarantine_result.json

UC05 — Config-driven entities

Why: add a table without cloning the whole pipeline — edit config.

sample_data/entities.json → ForEach enabled=true → out/uc05_entity_<name>.json → out/uc05_config_foreach_result.json

UC06 — Run audit trail

Why: compliance and ops need a guest book of runs, not tribal knowledge.

prior UC results → out/uc06_audit_trail.json (content_sha256) → out/playbook_summary.json
