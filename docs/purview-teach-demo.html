1. The big story (read this first)

Restaurant analogy (remember this for the whole class):

Imagine a busy restaurant kitchen (your Azure data estate).
• Raw ingredients arrive in the walk-in fridge → bronze (ADLS bronze).
• Chefs prep and clean → silver.
• Plated dishes go to the pass → gold.
• The kitchen manager’s timetable → Azure Data Factory (ADF).
• The recipe book + guest book that answers “where did this sauce come from?” → Microsoft Purview.

Without Purview, answering “which report uses which file?” means guessing and Slack threads. With Purview, you search an asset and open Lineage to see the graph of how data moved.

What you will be able to do after this page:

  • Explain Purview in one sentence using the restaurant analogy
  • Complete Section 0 — Do this in OUR lab (phase 3 + purview-demo.cmd + Lineage)
  • Find folder 13-governance-purview and name the six pl_gov_* pipelines
  • Know why ADF must have Data Curator on the Purview root collection
  • After the demo: open Section 4b — Governance detailed and answer the exit ticket

2. Concepts — what / why / analogy / lab / official source

2.1 Microsoft Purview (Data Governance)

What: A unified data governance service — catalog your data, who owns it, and how it flows.

Why: Enterprises need one place to discover assets and prove lineage for audits and debugging.

Analogy: The restaurant’s recipe book + guest book combined.

In this lab: Account pviewrohan4hnv7s (often under rg-rohan-class1, not always in the shared RG).

Source: Connect a Data Factory to Microsoft Purview

2.2 Data Map

What: The inventory layer — registered sources (ADLS, SQL, ADF) and assets discovered by scans or pushed by integrations.

Analogy: The kitchen’s inventory binder listing every fridge shelf and pantry jar.

In this lab: ADLS stsharedqgr7mj can be registered + scanned; ADF also pushes lineage into the map when connected.

2.3 Data Catalog / Asset

What: Searchable index of assets. An asset is one thing (a file path, table, report).

Analogy: Card catalog drawers — each card is one dish or ingredient SKU.

In this lab: Search sample_transactions, stsharedqgr7mj, loaded, cleaned, aggregates.

Common mistake: Searching the factory name adf-shared-qgr7mj often returns nothing. The factory is a process on the Lineage graph, not usually a catalog “file” asset.

2.4 Lineage

What: A directed graph showing how data moved: source → process → sink.

Analogy: CCTV of the kitchen pass — you see which station touched the plate.

Official behaviour (verified): When ADF is connected to Purview, supported activities (Copy, Data Flow, Execute SSIS) automatically push lineage during pipeline runs. No extra “lineage activity” is required inside the pipeline.

Sources: Connect ADF to Purview (lineage) · Tutorial: Push lineage to Purview · Classic lineage user guide

2.5 Glossary, classifications, ownership

Glossary

Business terms (e.g. Medallion.Bronze).

Menu definitions — what “chef’s special” means.

Lab: seeded conceptually via purview_catalog_template.json on ADLS audit/governance/.

Classifications

Sensitivity / labels (PII, Internal).

Allergy stickers on ingredients.

Lab: shown as Copy user properties + JSON template.

Ownership / stewardship

Who is accountable for an asset.

Head chef for each station.

Lab: documented in catalog JSON; assign in Purview Studio in production.

2.6 Scan / discovery vs ADF Get Metadata

Purview scan: Purview crawls a registered source on a schedule and registers new paths/tables into Data Map.

Nightly inventory count of the fridge.

Lab teaching shortcut: pl_gov_05 uses ADF Get Metadata (childItems) to teach the idea of discovery without always waiting on a full Purview scan (cheaper / faster for class).

2.7 ADF ↔ Purview connection

What: Factory setting points at your Purview account; ADF managed identity pushes lineage.

Required permission (verified): ADF managed identity needs Data Curator on the Purview root collection.

Giving the kitchen manager a key to write in the guest book.

Source: Connect Data Factory to Purview — authentication / Data Curator

4b. After the demo — what is the governance part? (detailed)

Students often ask: “We ran the demo — so what exactly is governance in Purview?” Read this section after purview-demo.cmd / pl_gov_06. Nothing below replaces Sections 0–4; it adds structure so the demo sticks.

One-line answer:

Governance in Purview = one place that answers what data we have, who owns it, how sensitive it is, and how it moved — it is not another ETL / transform pipeline.

Analogy: bronze/silver/gold move and cook the food; Purview is the recipe book + guest book that proves where each dish came from.

B. How the demo maps to governance (folder 13-governance-purview)

There is no pipeline named “Purview”. Governance = this folder + six pl_gov_* pipelines.

pl_gov_06 (MASTER) — end-to-end governance demo ├─ pl_gov_01 Bronze Copy → asset + classification tags ├─ pl_gov_02 Silver Data Flow → lineage (cleanse) ├─ pl_gov_03 Gold Data Flow → lineage (aggregate) ├─ pl_gov_04 Catalog Lookup → glossary / catalog workflow └─ pl_gov_05 Get Metadata+Copy→ discovery idea + lineage edge

Medallion path the governance pipelines track (they describe the flow; they do not replace it):

bronze/incoming │ pl_gov_01 Copy ▼ bronze/loaded │ pl_gov_02 Mapping Data Flow ▼ silver/cleaned │ pl_gov_03 Mapping Data Flow ▼ silver/aggregates ← logical GOLD layer (glossary still says Medallion.Gold)

C. What students must remember after the demo

  1. Governance ≠ transform
    Bronze / silver / gold move data. Purview describes and traces it.
  2. Lineage is automatic for supported ADF activities once Connected
    Copy, Mapping Data Flow (and Execute SSIS) push lineage — no extra “lineage activity” inside the pipeline. MS Learn: ADF lineage in Data Map
  3. Connected + Data Curator are required
    ADF Manage → Microsoft Purview = Connected. MI adf-shared-qgr7mj needs Data Curator on the Purview root collection.
  4. Use classic Purview portal for this class
    Turn New Microsoft Purview portal OFF. Search asset → open Lineage tab.
  5. Wait 5–30 minutes after first successful run before expecting full Lineage.
  6. Open ADLS teaching files
    Storage stsharedqgr7mj → container audit → folder governance/ → purview_catalog_template.json (glossary, classifications, assets, lineage edges).

7. Connect ADF to Purview (verified Microsoft steps)

Aligned with Connect a Data Factory to Microsoft Purview and ADF lineage in Data Map.

7.1 Check connection status in ADF

  1. ADF Studio → Manage (toolbox icon).
  2. Under Purview integration → Microsoft Purview.
  3. Status should be Connected to pviewrohan4hnv7s.
Verify: Connected. If Disconnected, Data Curator is usually missing (next step) or the factory was never linked (re-run phase 3 / purview-demo.cmd).

7.2 Grant Data Curator (one-time — classic Purview)

Microsoft docs: ADF uses its managed identity to push lineage. Grant that identity Data Curator on the Purview root collection.

  1. Open Purview account pviewrohan4hnv7s → governance portal.
  2. Turn OFF “New Microsoft Purview portal” (use classic for ADF lineage teaching).
  3. Data map → Collections / Access control → Root collection.
  4. Role assignments → Add → Role: Data Curator.
  5. Member: managed identity / SPN named adf-shared-qgr7mj → Save.
Verify: ADF Manage → Microsoft Purview shows Connected after refresh.

10. Optional — register & scan ADLS (if search is empty)

If catalog search finds almost nothing for storage paths, register the lake and scan it (Data Map).

  1. Classic Purview → Data map → Sources → Register.
  2. Source type: Azure Data Lake Storage Gen2.
  3. Account: stsharedqgr7mj (same subscription).
  4. New scan → include containers bronze, silver, audit → Run.
  5. Wait for scan success → return to Data catalog → search again.
Verify: Search stsharedqgr7mj or bronze returns assets.

Analogy: You cannot find a jar in the recipe book until someone inventories the fridge (scan).
