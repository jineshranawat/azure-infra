Extra problems, solved & documented

The core build covers the 50 problems. This module adds 11 advanced patterns (A1–A11) that senior teams hit in real programmes but which aren’t always spelled out: SCD1, CDC tombstones, content de-dup, column profiling, format-preserving PII, allowed-lateness, per-partition recon, schema evolution, backoff, as-of joins, idempotency. Each is a pure, unit-tested function in lib/advanced_patterns.py with a full docstring on every method — INPUT (Args), OUTPUT (Returns), Raises, and a Reference.

Where

transforms-python/src/myproject/lib/advanced_patterns.py · tests in src/test/test_advanced_patterns.py · live demo datasets/problems/advanced.py.

How documented

Each method: one-line summary, description, Args=inputs, Returns=output, Raises, and a Reference to the Palantir surface + DE pattern.

Proven

Every function has positive and negative pytest cases; CI runs them on each commit.

A1 · scd1_latest SCD Type 1

scd1_latest(records: Sequence[Mapping], key: str, order: str) -> List[dict]

Keep only the latest row per key (overwrite history). Contrast with SCD2 which keeps effective-dated history.

INPUTrecords rows; key natural-key field; order recency field (higher=newer) OUTPUTList[dict] — one newest row per key, first-seen key order
Reference: incremental transforms / dimension modelling · DE: SCD Type 1

A2 · classify_cdc_with_tombstones CDC + deletes

classify_cdc_with_tombstones(current: Mapping, previous: Mapping, tombstones: Sequence=None) -> Dict[key,str]

Classify every key as INSERT / UPDATE / UNCHANGED / DELETE, honouring explicit source hard-delete tombstones as well as implicit deletes.

INPUTcurrent key→value (new); previous key→value (old); tombstones keys deleted at source OUTPUTDict[key,str] — op per key
Reference: @incremental change feeds / CDC syncs · DE: CDC + tombstone deletes

A3 · content_hash / dedupe_by_hash content de-dup

content_hash(row: Mapping, cols: Sequence[str]) -> str dedupe_by_hash(rows: Sequence[Mapping], cols: Sequence[str]) -> List[dict]

De-duplicate by CONTENT (selected columns), catching “same record, different PK” duplicates a PK-only dedupe misses. First occurrence wins.

INPUTrows records; cols columns defining identity OUTPUTcontent_hash→ SHA-1 hex; dedupe_by_hash→ unique rows (first-seen order)
Reference: Data Expectations + Silver cleanse · DE: content-addressable de-duplication

A4 · profile_column observability

profile_column(values: Sequence) -> dict

Column health: count, nulls, null%, distinct, min, max — automatic profiling without a separate tool. This is the pattern surfaced live as rtt_data_profile.

INPUTvalues — all values of one column (Nones allowed) OUTPUTdict {count, nulls, null_pct (0..1|None), distinct, min, max}
Reference: Data Health / expectations · DE: column profiling / observability

A5 · tokenize_preserving format-preserving PII

tokenize_preserving(value: str|None, key: str) -> str|None

Format-preserving pseudonymisation: keeps character classes/length (digit→digit, upper→upper, punctuation kept) so format checks still pass while the real value is hidden. Deterministic per key. Complements one-way lib.pii.pseudonymise.

INPUTvalue e.g. 'NHS1000580'; key secret salt (stable joins) OUTPUTstr|None token with identical shape e.g. 'NHS7413926'
Reference: property security / Markings + in-pipeline PII · DE: FPE tokenisation

A6 · within_allowed_lateness late data

within_allowed_lateness(event_ts: date|None, watermark: date|None, allowed_days: int) -> bool|None

Decide whether a late/out-of-order event is still inside the allowed-lateness window relative to the stream watermark.

INPUTevent_ts event date; watermark current progress; allowed_days tolerance OUTPUTbool|None True=accept, False=too late, None=unknown
Reference: streaming / @incremental watermarking · DE: allowed lateness window

A7 · reconcile_by_partition recon

reconcile_by_partition(source_counts: Mapping, target_counts: Mapping) -> dict

Per-partition variance + a global balanced flag — catches a partition that gained rows while another lost them (a single total wouldn’t).

INPUTsource_counts/target_counts partition-key → row count OUTPUTdict {variances: {key: target-source}, balanced: bool}
Reference: recon control totals / audit · DE: partition-level reconciliation

A8 · merge_schemas schema evolution

merge_schemas(cols_a: Sequence[str], cols_b: Sequence[str]) -> List[str]

Order-preserving column superset for a fan-in union of frames with differing schemas (missing columns then null-filled). Safe additive schema drift.

INPUTcols_a, cols_b — the two column lists OUTPUTList[str] cols_a then columns only in cols_b
Reference: transforms fan-in / union; schema drift · DE: schema evolution

A9 · backoff_schedule resilience

backoff_schedule(max_retries: int, base=1.0, factor=2.0, cap=30.0) -> List[float]

Exponential backoff delays (seconds), each capped — the retry policy for a flaky connector.

INPUTmax_retries(≥0), base(>0), factor(≥1), cap OUTPUTList[float] delay before each attempt RAISESValueError on invalid params
Reference: Data Connection sync retry/throttle · DE: exponential backoff

A10 · as_of_join_pick point-in-time

as_of_join_pick(fact_ts: date, dim_versions: Sequence[(date,value)]) -> value|None

Return the dimension value effective at fact_ts (latest valid_from ≤ fact_ts). Prevents joining today’s dimension onto a historical fact.

INPUTfact_ts fact date; dim_versions list of (valid_from, value) OUTPUTvalue|None effective value, or None if none applies
Reference: SCD2 + link resolution · DE: as-of / point-in-time join

A11 · idempotency_key exactly-once

idempotency_key(parts: Sequence) -> str

Deterministic key from the components that define one logical write — replay-safe / exactly-once writes on top of immutable transactions.

INPUTparts e.g. [source, batch_id, pk] OUTPUTstr stable 24-char hex; identical inputs => identical key
Reference: immutable transactions + idempotent replay (Problem 19) · DE: idempotency key
