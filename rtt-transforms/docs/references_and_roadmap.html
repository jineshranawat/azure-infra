Newly implemented from the docs

The core pipeline used only primary_key, non_null, gte/lte/gt, equals, all. New transform datasets/problems/expectations_showcase.py → rtt_clean_certified now implements the documented but previously-unused expectations:

E.schema().contains({"pathway_id": pl.String, "trust_code": pl.String, "weeks_waited": pl.Int64})  # schema
E.group_by("pathway_id").is_unique()                       # composite uniqueness
E.col("trust_code").is_in("TR001","TR002","TR003","TR004","TR005")   # membership (FAILS on null)
E.col("specialty_code").rlike(r"^SP\d{2}$")               # regex
E.when(E.col("pathway_status").equals("Active"), E.col("weeks_waited").gte(0)).otherwise(E.true())  # conditional
E.col("weeks_waited").has_type(pl.Int64)                   # column type
E.col("nhs_number").null_percentage().lt(0.01)             # aggregate
E.group_by().count().gt(0)                                  # row count
E.col("specialty_name").exists()                            # column existence

Reference: foundry/transforms-python/unit-tests → Expectation types quick reference. Each is annotated in-code with its doc reference.

Round 2 - previously Pending/Partial, now implemented (built & green)

  • Foreign key + cross-column + freshness → problems/referential_checks.py → rtt_clean_ri_checked: is_in_foreign_col (trust_code → provider_reference), is_before_col (referral before load), is_after (parsed timestamp).
  • Advanced @incremental → problems/incremental_advanced.py → rtt_pathways_delta: semantic_version, ctx.abort_job() no-data pattern, .with_resources(cpu_cores, memory_gb), idempotency-key stamping.

Gotcha learned & fixed via CI: E.dataset_ref(...) takes the transform’s input parameter name (e.g. "providers"), not the dataset path.

from datetime import timedelta
E.col("event_ts").timestamp_offset_to_current_time().lt(timedelta(hours=24))   # data within 24h
